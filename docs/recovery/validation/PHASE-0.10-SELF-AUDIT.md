# Phase 0.10 Self-Audit — Shared Electronic-Signature Credential Containment

Date: 2026-08-23

## Scope and intended outcome

Remove all API acceptance of shared hard-coded passwords as electronic-signature verification. Prevent the affected regulated mutations and misleading signature/audit evidence while preserving permission-controlled CAPA updates that do not close or claim an electronic signature.

## Change review

- CAPA `CLOSED` requests now return non-cacheable `503 ElectronicSignatureDisabled` after authentication and closure permission evaluation but before CAPA lookup, transaction, or audit access.
- CAPA status is trimmed and uppercased before authorization and mutation so case/whitespace variants cannot bypass closure containment.
- Removed the CAPA shared-password comparison and failed-signature best-effort audit path.
- Kept non-closure CAPA updates under `capa.update`, mandatory transactional audit, and `eSigned: false` evidence.
- Replaced equipment maintenance/calibration POST with a no-argument fail-closed handler.
- Replaced supplier-audit POST with a no-argument fail-closed handler.
- Added `ESIGN-T001` through `ESIGN-T004` for former credential rejection, zero side effects, and retained non-signature behavior.

## Architecture, security, tenancy, GxP, UI, and data-integrity audit

- **Identity:** no shared constant can authenticate a signer through these routes.
- **Authorization:** CAPA closure still evaluates authentication and `capa.approve_close` before reporting temporary unavailability; the two wholly disabled handlers cannot parse any request.
- **Tenant isolation:** disabled paths cannot select or mutate a tenant record. Retained CAPA updates use tenant-scoped `findFirst`.
- **Electronic signatures:** no new signature ID, signed claim, equipment log, supplier-audit decision, closure timestamp, or successful signature audit can be generated by the contained paths.
- **Data integrity:** CAPA non-closure updates keep their database mutation and mandatory audit in one transaction. The other affected mutations are unavailable.
- **UI:** existing controls may receive a temporary-unavailable response; UI removal/disabled-state messaging is residual work.
- **Legal/validation:** containment avoids representing shared credentials as an individual signature. It does not implement or validate a compliant electronic-signature process.
