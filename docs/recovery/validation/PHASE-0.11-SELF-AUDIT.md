# Phase 0.11 Self-Audit — Non-Core Equipment and Supplier Mutation Containment

Date: 2026-08-23

## Scope and intended outcome

Prevent equipment and supplier mutations that currently lack canonical membership permissions. Make equipment GET a tenant-scoped domain read that cannot change equipment status or create deviations. Retain read access temporarily for recovery visibility; explicit read permissions remain future work.

## Change review

- Rebuilt equipment GET as one tenant-scoped query with no overdue-calibration update loop, deviation creation, or second refresh query.
- Sanitized equipment-list failure responses instead of returning raw internal error messages.
- Replaced equipment POST with no-argument `503 EquipmentMutationDisabled`.
- Preserved supplier GET as a tenant-scoped recovery read and sanitized its failure response.
- Changed retained equipment/supplier read-event attribution from operational `User.role` to the authenticated IAM membership role.
- Replaced supplier POST, PUT, and DELETE with no-argument `503 SupplierMutationDisabled` responses.
- Replaced supplier material-receipt POST with a no-argument fail-closed response.
- Equipment maintenance and supplier-audit signature mutations remain disabled from Phase 0.10.
- Added `NONCORE-T001` through `NONCORE-T006`.

## Architecture, security, tenancy, GxP, UI, and data-integrity audit

- **Product architecture:** mutations in non-core domains remain unavailable rather than being added to the temporary static RBAC model.
- **Authorization:** disabled methods do not authenticate or parse requests because no mutation is possible; eventual re-enablement requires membership-derived permissions.
- **Tenant isolation:** retained list reads use `where: { tenantId: user.tenantId }`; single-record routes still post-check tenant ownership.
- **HTTP semantics:** equipment GET no longer changes equipment state or creates deviations. Security access logging remains best-effort and does not change equipment-domain records.
- **Data integrity:** no new equipment, attachment, supplier, material receipt, or auto-deviation record can be generated by the contained methods.
- **Error disclosure:** modified GET handlers return sanitized failure messages.
- **UI:** mutation controls may still submit and receive `503`; proactive disabled-state messaging is residual work.
- **Legal/validation:** the change reduces unauthorized regulated-record creation but is not a validation or compliance claim.
